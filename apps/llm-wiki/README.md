# LLM Wiki Memory Kernel

The LLM Wiki is the canonical durable-memory layer beneath the 222Emails / OMEGA operating system.

It is local-first and cheap-first:

- Markdown and JSON remain durable truth.
- SQLite FTS5 is disposable/rebuildable retrieval state.
- Hybrid retrieval improves concept matching without paid embeddings.
- Historical ChatGPT conversations are indexed as evidence, never silently promoted to truth.
- Meaningful user instructions are distilled into a review-only memory-candidate queue.
- Live operational state stays in its live system and is queried at source.
- Connector snapshots are indexed separately and always marked volatile.
- Every durable/chat retrieval retains provenance.
- Agent writes to canonical knowledge remain proposal-first unless explicitly approved.
- MCP exposes read-only memory tools, not canonical mutation tools.

## V3 operating loop

1. **Ingest durable knowledge** from approved repository sources.
2. **Backfill historical conversations** from `conversations.json` or the reviewed OMEGA migration CSV.
3. **Incrementally ingest new conversation events** through JSONL when a ChatGPT/runtime bridge emits them.
4. **Distil candidates** for rules, decisions, preferences and open loops. Candidates stay `review` until promoted by an authorised workflow.
5. **Retrieve through ChatGPT-standard `search` / `fetch`** with durable sources ranked before historical chat evidence.
6. **Import connector snapshots** only for discovery/context acceleration.
7. **Govern canonical truth** with lint, staleness and contradiction checks.
8. **Verify volatile facts live** before consequential action.

## Quick start

Requires Python 3.11+ and no third-party packages.

```bash
cd apps/llm-wiki
python -m src.cli init
python -m src.cli ingest --repo ../..

# Existing reviewed OMEGA migration sheet
python -m src.cli chat-migration-import /path/to/OMEGA_75_Chat_Migration.csv

# Full ChatGPT history export when available
python -m src.cli chat-backfill /path/to/conversations.json

# Incremental future messages
python -m src.cli chat-ingest /path/to/events.jsonl

python -m src.cli chat-search "local salon campaign"
python -m src.cli memory-candidates --limit 50
python -m src.cli context "revenue recovery offer" --limit 8
python -m src.cli lint --fail-on-error
python -m src.cli stats
python -m src.cli serve-mcp --host 127.0.0.1 --port 8765
```

The generated database defaults to `.data/wiki.db` and must not be committed.

## Historical ChatGPT backfill

### Raw export

`chat-backfill` supports the standard ChatGPT `conversations.json` structure. For branched conversations it follows the active `current_node` ancestry so abandoned branches do not pollute memory. Re-running the same export is idempotent by message/content hash.

### Existing OMEGA migration sheet

`chat-migration-import` supports the reviewed migration CSV generated by the earlier OMEGA 75-chat workflow. It imports canonical title, summary, decisions, open loops, next action, current state and supersession evidence. Structured decisions/open loops enter the same review queue and do **not** automatically become canonical facts.

### Candidate policy

The deterministic zero-cost distiller recognises likely:

- rules
- decisions
- preferences
- open loops
- explicit supersession cues

Every extracted item starts with `status=review`. Historical messages and candidates are evidence only. Canonical promotion is deliberately outside the read-only MCP surface.

## Incremental ChatGPT event contract

JSONL, one record per line:

```json
{"conversation_id":"abc","message_id":"m123","role":"user","text":"From now on, always use UK English.","created_at":1788073200,"title":"Operating rules"}
```

The event importer is idempotent by message id plus content hash. A runtime bridge can therefore retry safely.

## Connector snapshot contract

Connector ingestion accepts JSON or JSONL. A record must contain:

```json
{
  "source": "gmail",
  "external_id": "message-or-thread-id",
  "title": "Human-readable title",
  "content": "Searchable snapshot content",
  "uri": "gmail://optional-source-uri",
  "observed_at": "2026-08-30T01:00:00Z",
  "expires_at": null,
  "metadata": {"thread_id": "optional"}
}
```

Connector records are never promoted into canonical durable truth merely because they were ingested. Results carry `volatile=true` and `verification_required=true`.

## ChatGPT / MCP surface

The server exposes `/mcp` and supports the current stateless request model plus compatibility `initialize`, `notifications/initialized` and `ping` handling.

Primary ChatGPT-facing tools:

- `search`: searches durable Wiki sources first and optionally historical conversation evidence.
- `fetch`: fetches the exact bounded result returned by `search`.

Existing specialist tools remain available:

- `wiki_search`
- `wiki_context`
- `connector_search`
- `wiki_health`

All tools are read-only, idempotent, non-destructive and closed-world. Historical chat results are explicitly returned as `source_class=historical_evidence`, `canonical_status=noncanonical`. Volatile connector results still require live verification.

The local CLI refuses a non-loopback bind. Production ChatGPT use requires a stable public HTTPS deployment or authenticated wrapper around `/mcp`.

## Governance

Documents can opt into high-confidence canonical contradiction detection using metadata/frontmatter:

```yaml
---
status: CURRENT CANONICAL
canonical_key: primary_market
canonical_value: UK
updated: 2026-08-30
---
```

If two active canonical sources declare different values for the same `canonical_key`, lint raises an error and agents must not guess.

## Truth hierarchy

1. Live system of record for volatile facts.
2. Newest explicitly current-canonical durable source.
3. Approved Wiki synthesis.
4. Reviewed historical migration evidence.
5. Raw chat history.
6. Inference, which must never be silently promoted to fact.

## External activation boundary

The repository cannot independently read a private ChatGPT sidebar/history. A historical raw backfill therefore requires a ChatGPT data export, while the already-reviewed OMEGA migration CSV can be imported immediately. Continuous future capture requires the ChatGPT/runtime layer to emit the documented JSONL events or call an equivalent authenticated ingestion service.

Likewise, connecting this private memory app inside ChatGPT requires a reachable HTTPS MCP endpoint and enabling the app in ChatGPT Developer Mode. The repository is deployment-ready, but credentials/private history are intentionally not embedded in source control.
